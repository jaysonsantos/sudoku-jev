sudoku-jev · how the loop works

Jev never solves the sudoku. It picks one legal placement from a list, over and over.

Jev is a decision model. It takes a state and a set of questions with fixed options, and returns one option per question with a probability for every option. The app turns each turn of the game into exactly that shape: the board is the state, every legal placement is an option, and the browser judges the answer.

03 · the choices

The question: every legal placement is one option

The backend computes the candidates. Only placements that break no row, column, or box rule become options, minus the ones the browser already rejected. This puzzle had 135 legal placements, so one question. An option id reads like a sentence, and its description is a small object: the position, the digit, and every digit that still fits in that cell.

Why 255 matters

Jev accepts at most 255 options per choice question. An empty board has 729 placements. The backend slices the list into move_batch_1, move_batch_2, ... and sends all batches in one request. Jev answers them in parallel.

Why cell_candidates

Jev does not count or calculate. The code computes which digits fit in each cell and puts the list in every option. A single-digit list is the visible signal that the instructions ask it to prefer.

Why an id like a sentence

row_1_col_6_value_5 is the option key Jev returns. The backend parses it back into {row: 0, col: 5, value: 5} with a regex. No free text ever comes back.

With several batches, each question names its own winner. The backend ignores the choice fields and takes the single highest probability across all batches, then reports the confidence of the batch it came from.

05 · who judges

The browser owns the solution. Jev is never told if it was right.

Correct value

The move matches the hidden solution. The cell fills in blue and the next state goes out after a short delay so the board stays readable.

Wrong value

Cell stays empty, shown red with a strike. The move joins rejected, so the backend never offers it again. Mistakes count goes up.

Won

No empty cell left. Status becomes won, the loop stops, and the Solve button disables until New game.

Lost

Three mistakes. Status becomes lost. The server also declares a loss when no legal move remains after the rejections.

Feedback reaches Jev only indirectly: a wrong option disappears from the next list, and a right one shows up as a filled digit in the next state rows.
